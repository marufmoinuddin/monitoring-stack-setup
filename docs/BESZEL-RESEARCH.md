# Beszel's one-liner — how it actually works

Researched from the live installer, the hub source, and the UI source.

## The command

```
curl -sL https://get.beszel.dev -o /tmp/install-agent.sh \
  && chmod +x /tmp/install-agent.sh \
  && /tmp/install-agent.sh -p 45876 -k "ssh-ed25519 AAAA..." -t "uuid" -url "https://hub"
```

Three ingredients, all pre-generated by the admin panel:
- `-p 45876`  — the port the agent listens on **for its own admin UI**
- `-k`        — the **hub's public key** (the agent signs with the matching private key)
- `-t`        — a UUID token identifying this system in the hub DB

## The installer is a script, not a binary blob

`https://get.beszel.dev` returns **50 KB of POSIX shell**, not a compiled blob.
That is the single most important design decision: the user can read every byte
before running it. 1465 lines, 39 functions, `#!/bin/sh` with `set -eu`.

It:
1. Detects OS (Linux/Alpine/OpenWrt/FreeBSD/OPNsense/pfSense/macOS) and refuses
   unknown platforms with a clear message.
2. Detects arch from `uname -m`, including MIPS endianness read out of the ELF
   header (byte 6: `01` little, `02` big).
3. Ensures `tar`, `curl`, `sha256sum` via a package-manager ladder:
   apk -> opkg -> pkg (FreeBSD) -> apt-get -> yum -> pacman.
4. Fetches the version from `https://get.beszel.dev/latest-version`, falling back
   to the GitHub API.
5. Downloads `checksums.txt` **first**, then the archive, and refuses to proceed
   unless the SHA-256 matches. Validates the tarball before extracting.
6. Installs a systemd unit (plus OpenRC / procd / FreeBSD rc variants),
   handling SELinux contexts and OpenWrt's uid constraints.

## The trust chain is public-key, not secret-based

This is the part worth copying. From `internal/hub/agent_connect.go`:

```go
signer, _ := acr.hub.GetSSHKey("")                       // hub holds the PRIVATE key
agentFingerprint, _ := wsConn.GetFingerprint(ctx, token, signer, ...)
```

The **hub holds the private key and the agent holds the public key**. On connect
the agent returns a *fingerprint* it has signed; the hub verifies the signature
against its own private key. The `-k` value in the install command is therefore a
**public key — safe to display, copy, and paste into chat.**

Consequences:
- The install command contains no secret. Leaking it leaks nothing.
- Identity is cryptographic, not a shared password that could be replayed.
- A *fingerprint* (derived from host identity) is bound to the token on first
  connect. A later connect from the same token with a different fingerprint is
  rejected: `fingerprint mismatch`. That is copy-protection on the token.

## The connection is OUTBOUND, like mine

`handleAgentConnect` upgrades to a WebSocket. The agent dials the hub; the hub
never connects to the agent. So like our design there is **no inbound port on the
client** — but unlike ours there is no SSH reverse tunnel either. It is a plain
reverse WebSocket over 443.

That is the real architectural difference:
- **Ours:** hub -> http-over-ssh -> SSH reverse tunnel -> client sshd -> exporter.
  Every scrape is a new SSH connection. Needs sshd, `promssh`, PermitListen,
  known_hosts pinning per device.
- **Beszel:** agent -> WebSocket -> hub, one persistent connection. Needs no
  sshd, no tunnels, no host-key pinning. Identity is a signed fingerprint.

## The UI just formats a string

`internal/site/src/components/install-dropdowns.tsx`:

```ts
`curl -sL ${getScriptUrl()} -o /tmp/install-agent.sh && chmod +x /tmp/install-agent.sh && /tmp/install-agent.sh -p ${port} -k "${publicKey}" -t "${token}" -url "${getHubURL()}"`
```

Plus Docker Compose and `docker run` variants, and a PowerShell one for Windows.
The token and key are minted when you click "create system" in the UI.

## What to replicate, and what not to

Replicate:
1. **Installer as readable POSIX shell** served from a stable URL.
2. **`/latest-version` endpoint** so the installer can resolve a version.
3. **Checksums-first, verify-before-extract**, with a mirror override.
4. **Public key in the command, not a secret.**
5. **Package-manager ladder** across distros.
6. **Platform refusal** with an actionable message.
7. **An admin panel that mints the command** and copies it to the clipboard.

Do NOT replicate:
- Writing a whole new Go hub + React app. We already have Grafana; the panel
  only has to mint and hand out the command, then show target health.
- WebSocket transport. Our SSH tunnel path is proven and adds zero open ports;
  changing the transport is a rewrite, not an improvement.

## Our equivalent mapping

| Beszel | Ours |
|---|---|
| `get.beszel.dev` installer | `get.<your-domain>` shell installer |
| `/latest-version` | same |
| hub holds private key, agent signs | keep SSH host-key pinning (equivalent guarantee) |
| fingerprint bound to token | tunnel port 2201/2202/2203 bound one-key-per-device |
| admin panel mints copy command | `monitor-admin.<domain>` panel |
| agent -> WebSocket -> hub | client autossh -> tunnel -> proxy -> exporter |
